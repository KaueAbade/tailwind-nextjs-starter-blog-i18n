# Blog Starter Tailwind Nextjs

![Deploy com Vercel](https://vercel.com/button)](https://vercel.com/new/git/external?repository-url=https://github.com/timlrx/tailwind- nextjs-starter-blog)

> [!CAUTION]
> Este é o README da versão 1 do template. Ele é mantido por razões históricas, mas não é mais válido. Também serve como exemplo principal para [Github Alert](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#alerts). Para a documentação atual, consulte o [repositório do Github](https://github.com/timlrx/tailwind-nextjs-starter-blog).

Este é um modelo de blog inicial em [Next.js](https://nextjs.org/), [Tailwind CSS](https://tailwindcss.com/). Provavelmente o modelo de blog Markdown em Next.js mais rico em funcionalidades. Pronto para uso, configurado com as tecnologias mais recentes para facilitar a escrita técnica. Facilmente configurável e personalizável. Perfeito para substituir blogs individuais existentes em Jekyll e Hugo.

Consulte a documentação abaixo para começar.

Pedido de funcionalidade? Verifique as discussões anteriores para ver se já foi mencionado. Caso contrário, sinta-se à vontade para criar uma nova thread de discussão. Todas as ideias são bem-vindas!

## Motivação

Eu queria portar meu blog existente para Next.js e Tailwind CSS, mas não havia um modelo pronto para uso fácil de utilizar, então decidi criar um. O design é adaptado do [blog do Tailwindlabs](https://github.com/tailwindlabs/blog.tailwindcss.com).

Eu queria que fosse quase tão rico em funcionalidades quanto os modelos de blog populares como [beautiful-jekyll](https://github.com/daattali/beautiful-jekyll) e [Hugo Academic](https://github.com/wowchemy/wowchemy-hugo-modules), mas com o melhor do ecossistema React e as melhores práticas atuais de desenvolvimento web.

## Funcionalidades

- Personalização fácil de estilo com [Tailwind 3.0](https://tailwindcss.com/blog/tailwindcss-v3) e atributo de cor primária
- Pontuação quase perfeita no Lighthouse - [Relatório Lighthouse](https://www.webpagetest.org/result/210111_DiC1_08f3670c3430bf4a9b76fc3b927716c5/)
- JS leve de 45 Kb no primeiro carregamento, usa Preact na build de produção
- Visualização adaptada para dispositivos móveis
- Tema claro e escuro
- Fonte auto-hospedada com [Fontsource](https://fontsource.org/)
- Suporte para [plausible](https://plausible.io/), [simple Analytics](https://simpleanalytics.com/) e Google Analytics
- [MDX - escreva JSX em documentos markdown!](https://mdxjs.com/)
- Destaque de sintaxe no lado do servidor com números de linha e destaque de linhas via [rehype-prism-plus](https://github.com/timlrx/rehype-prism-plus)
- Exibição matemática suportada via [KaTeX](https://katex.org/)
- Suporte para citações e bibliografia via [rehype-citation](https://github.com/timlrx/rehype-citation)
- Otimização automática de imagens via [next/image](https://nextjs.org/docs/basic-features/image-optimization)
- Busca de dados flexível com [mdx-bundler](https://github.com/kentcdodds/mdx-bundler)
- Suporte para tags - cada tag única terá sua própria página
- Suporte para múltiplos autores
- Modelos de blog
- Componente de sumário (TOC)
- Suporte para roteamento aninhado de publicações do blog
- Componente de newsletter com suporte para mailchimp, buttondown e convertkit
- Suporte para [giscus](https://github.com/laymonage/giscus), [utterances](https://github.com/utterance/utterances) ou disqus
- Página de projetos
- Cabeçalhos de segurança pré-configurados
- Otimizado para SEO com feed RSS, sitemaps e muito mais!

## Guia de início rápido

1. JS (suporte oficial) - `npx degit https://github.com/timlrx/tailwind-nextjs-starter-blog.git` ou TS (suporte da comunidade) - `npx degit timlrx/tailwind-nextjs-starter-blog #typescript`
2. Personalize `siteMetadata.js` (informações relacionadas ao site)
3. Modifique a política de segurança de conteúdo em `next.config.js` se quiser usar
    qualquer provedor de analytics ou uma solução de comentários diferente do giscus.
4. Personalize `authors/default.md` (autor principal)
5. Modifique `projectsData.js`
6. Modifique `headerNavLinks.js` para personalizar os links de navegação
7. Adicione publicações ao blog
8. Faça o deploy na Vercel

## Desenvolvimento

Primeiro, execute o servidor de desenvolvimento:

```bash
npm start
# or
npm run dev
```

Abra [http://localhost:3000](http://localhost:3000) no seu navegador para ver o resultado.

Você pode começar a editar a página modificando `pages/index.js`. A página se atualiza automaticamente conforme você edita o arquivo.

## Estender / Personalizar

`data/siteMetadata.js` - contém a maior parte das informações relacionadas ao site que devem ser modificadas conforme a necessidade do usuário.

`data/authors/default.md` - informações do autor padrão (obrigatório). Autores adicionais podem ser incluídos como arquivos em `data/authors`.

`data/projectsData.js` - dados usados para gerar um cartão estilizado na página de projetos.

`data/headerNavLinks.js` - links de navegação.

`data/logo.svg` - substitua pelo seu próprio logo.

`data/blog` - substitua pelas suas próprias publicações de blog.

`public/static` - armazena recursos como imagens e favicons.

`tailwind.config.js` e `css/tailwind.css` - contêm a folha de estilo tailwind que pode ser modificada para alterar a aparência geral do site.

`css/prism.css` - controla os estilos associados aos blocos de código. Sinta-se à vontade para personalizá-lo e usar seu tema prismjs preferido, por exemplo. [temas prism](https://github.com/PrismJS/prism-themes).

`components/social-icons` - para adicionar outros ícones, basta copiar um arquivo svg de [Simple Icons](https://simpleicons.org/) e mapeá-los em `index.js`. Outros ícones usam [heroicons](https://heroicons.com/).

`components/MDXComponents.js` - passe seu próprio código JSX ou componente React especificando-o aqui. Você pode então chamá-los diretamente no arquivo `.mdx` ou `.md`. Por padrão, um componente de link e imagem personalizado é passado.

`layouts` - modelos principais usados nas páginas.

`pages` - páginas para as quais rotear. Leia a [documentação do Next.js](https://nextjs.org/docs) para mais informações.

`next.config.js` - configuração relacionada ao Next.js. Você deve adaptar a política de segurança de conteúdo se quiser carregar scripts, imagens etc. de outros domínios.

## Artigo

### Frontmatter

O Frontmatter segue os [padrões do Hugo](https://gohugo.io/content-management/front-matter/).

Atualmente, 10 campos são suportados.

```
title (obrigatório)
date (obrigatório)
tags (obrigatório, pode ser um array vazio)
lastmod (opcional)
draft (opcional)
summary (opcional)
images (opcional, se nenhum for fornecido, usa o padrão socialBanner na configuração de siteMetadata)
authors (opcional, lista que deve corresponder aos nomes de arquivo em `data/authors`. Usa "default" se nenhum for especificado)
layout (opcional, lista que deve corresponder aos nomes de arquivo em `data/layouts`)
canonicalUrl (opcional, URL canônica para a publicação, para SEO)
```

Aqui está um exemplo de frontmatter de artigo:

```
---
title: 'Apresentando o Blog Starter Tailwind Nextjs'
date: '2021-01-12'
lastmod: '2021-01-18'
tags: ['next-js', 'tailwind', 'guide']
draft: false
summary: 'Procurando um modelo performático e pronto para uso, com o melhor da tecnologia web para atender às suas necessidades de blog? Confira o modelo Blog Starter Tailwind Nextjs.'
images: ['/static/images/canada/mountains.jpg', '/static/images/canada/toronto.jpg']
authors: ['default', 'sparrowhawk']
layout: PostLayout
canonicalUrl: https://tailwind-nextjs-starter-blog.vercel.app/blog/introducing-tailwind-nextjs-starter-blog
---
```

### Compor

Execute `node ./scripts/compose.js` para iniciar uma nova publicação.

Siga o prompt interativo para gerar um artigo com os elementos de frontmatter pré-preenchidos.

## Deploy

**Vercel**
A maneira mais fácil de fazer deploy do modelo é usar a [Plataforma Vercel](https://vercel.com) dos criadores do Next.js. Confira a [documentação de deploy do Next.js](https://nextjs.org/docs/deployment) para mais detalhes.

**Netlify / GitHub Pages / Firebase, etc.**
Como o modelo usa `next/image` para otimização de imagens, configurações adicionais devem ser feitas para deploy em outros sites populares de hospedagem estática como [Netlify](https://www.netlify.com/) ou [GitHub Pages](https://pages.github.com/). Outro provedor de otimização de imagens, como Imgix, Cloudinary ou Akamai, deve ser usado. Você também pode substituir o componente `next/image` por uma tag `<img>` padrão. Veja a [documentação do `next/image`](https://nextjs.org/docs/basic-features/image-optimization) para mais detalhes.

As rotas de API usadas no componente de newsletter não podem ser usadas em uma exportação de site estático. Você precisará usar um provedor de endpoint de API de formulário e substituir a rota no componente de newsletter conforme necessário. Outras plataformas de hospedagem, como a Netlify, também oferecem soluções alternativas - consulte a documentação delas para mais informações.
