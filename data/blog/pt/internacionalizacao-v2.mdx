## Novas funcionalidades

Este repositório será atualizado periodicamente com novas funcionalidades (não presentes no repositório original)
Tudo isso pode às vezes parecer obsessivo em relação à interface e aos detalhes — talvez excessivamente cuidadoso ou um pouco exagerado — mas também uso este repositório como um espaço de experimentação e aprendizado.

Por enquanto:
- Novo componente "sidetoc": exibe automaticamente o sumário dos seus artigos em uma sidebar dedicada.
- Integração de e-mail, tema, além de um botão para copiar rapidamente a URL da página em que você está, com o comando da paleta kbar.
A motivação para isso veio de explorar outras bibliotecas de paletas de comando, algumas oferecendo elementos aninhados para "Actions". Infelizmente isso não é possível com o kbar, mas me deu novas ideias!
- Funcionalidade multi-autores para a seção "sobre": cada autor pode ter sua própria página "sobre" disponível em um menu suspenso em telas grandes, ou exibida diretamente em telas pequenas. Se você quiser desativá-la e usar apenas a seção "sobre" normal e clássica, vá até sitemetadata.js e defina multiauthors como false. De qualquer forma, seu autor principal agora deve ter o campo "default" definido como true.
- Seção "Destaques" na página inicial para os artigos que você deseja fixar no topo: defina featured como true (máximo de dois artigos por padrão, pode ser modificado no arquivo Featured.tsx, na pasta component). O programa escolherá os dois artigos mais recentes com "featured: true". Se nenhum artigo em destaque estiver disponível, essa seção simplesmente não será exibida!
- Cada tag agora tem sua própria paginação! Se o número de artigos for maior do que o definido por você (padrão definido como 5), uma nova página é automaticamente criada para os artigos seguintes que incluem a mesma tag.
- O sistema de comentários Waline agora é suportado! É provavelmente o melhor sistema de comentários open source do momento, com suporte a i18n e muitos outros recursos interessantes! Primeiro, siga [o tutorial oficial](https://waline.js.org/en/guide/get-started/) para configurar o banco de dados de comentários e seu servidor vercel. Existem muitas opções disponíveis, então reserve um tempo para ler a documentação deles. Como é baseado em Vue, ele continua compatível com Next.js, e criei um novo componente de comentários. Você o encontrará na pasta "walinecomponents". Também adicionei um novo arquivo css, e você pode modificar o estilo aqui se necessário. Depois de fazer o deploy da sua aplicação para os comentários, modifique o arquivo sitemetadata.js. Defina a propriedade "iscomments" como false, defina "iswaline"
como true e defina a URL do seu servidor de comentários adequadamente em "walineServer". Se o seu idioma não for suportado pelo waline, abra um pull request no repositório deles ou peça gentilmente para que adicionem sua própria tradução (fornecendo-a você mesmo previamente). Foi o que fiz para dar suporte ao francês, e é assim que trabalhamos no mundo open source!

É, portanto, nesta pasta i18n que reside a lógica principal para a internacionalização da aplicação.

- Arquivos json:

A subpasta "locales" contém os arquivos .json onde você definirá suas traduções, sendo a convenção definir um arquivo por página do seu site, com o nome da página correspondente como nome do arquivo json.
Há também um arquivo "common": se você não especificar um "namespace" ou ns (o nome do arquivo sem a extensão json) em suas páginas ou componentes, as traduções serão buscadas neste arquivo por padrão.

*Importante: para cada idioma, deve haver um arquivo correspondente com o mesmo nome, por exemplo um arquivo "about" para "fr" e para "en", etc. Assim como chaves de tradução com o mesmo nome dentro
de cada arquivo.

Exemplo:

Em inglês, na pasta "en":

```json:projects.json

  "title": "Projects",
  "description": "Showcase your projects with a hero image (16 x 9)",
  "learn": "Learn more",
  "subtitle": "Here you will find information about my current projects",
  "linkto": "Link to"
}
```

Em francês, na pasta "fr":

```json:projects.json

  "title": "Projets",
```

- locales.js:

Este é o arquivo onde você definirá os idiomas que deseja usar, bem como o idioma padrão:

```js:locales.js
const fallbackLng = 'en' // idioma padrão
const secondLng = 'fr' 

module.exports = { fallbackLng, secondLng }
```

Você pode adicionar quantos idiomas quiser:

```js:locales.js

const fallbackLng = 'en'

module.exports = { fallbackLng, secondLng, thirdLng }
```

No entanto, isso exigirá algumas etapas de configuração adicionais em outros arquivos (principalmente arquivos que são discutidos neste artigo)

Você também pode inverter o idioma padrão e o segundo idioma:

```js:locales.js

const fallbackLng = 'fr'
const secondLng = 'en'

module.exports = { fallbackLng, secondLng}
```

- settings.ts

Este é um arquivo de configuração, que permite definir um objeto locales, bem como as opções correspondentes:

```ts:settings.ts
import type { InitOptions } from 'i18next'
import { fallbackLng, secondLng } from './locales'

/* Objeto locales, que define todos os idiomas que serão usados na aplicação: */
export const locales = [fallbackLng, secondLng] as const
/* Definição typescript de tipo para nossas locales:*/
export type LocaleTypes = (typeof locales)[number]
/* "Namespace" (ou ns) padrão: as traduções serão buscadas no arquivo 
common.json se nenhum ns for especificado em seus componentes ou páginas: */
export const defaultNS = 'common' 
/* Função que será reutilizada nos arquivos client.ts e server.ts: */
export function getOptions(locale = fallbackLng, ns = defaultNS): InitOptions {
  return {
    debug: true,
    supportedLngs: locales,
    fallbackLng,
    lng: locale,
    fallbackNS: defaultNS,
    defaultNS,
    ns,
  }
}
```

- client.ts e server.ts:

Sem entrar em detalhes complexos, esses dois arquivos exportam, cada um,
uma função para a tradução (useTranslation no lado do cliente, createTranslation no lado do servidor),
reutilizáveis em suas páginas e componentes:

```ts:client.ts
export function useTranslation(lng: LocaleTypes, ns: string) {
  const translator = useTransAlias(ns)
  const { i18n } = translator

  /* Executado quando o conteúdo é renderizado no lado do servidor: */
  if (runsOnServerSide && lng && i18n.resolvedLanguage !== lng) {
    i18n.changeLanguage(lng)
  } else {
    /* Usar nossa implementação personalizada durante a execução no lado do cliente: */
    // eslint-disable-next-line react-hooks/rules-of-hooks
    useCustomTranslationImplem(i18n, lng)
  }
  return translator
}
```

```ts:server.ts
export async function createTranslation(lang: LocaleTypes, ns: string) {
  const i18nextInstance = await initI18next(lang, ns)

  return {
    /* A função de tradução "t" que usaremos em nossos componentes: */
    // e.g. t('greeting')
    t: i18nextInstance.getFixedT(lang, Array.isArray(ns) ? ns[0] : ns),
  }
}
```

- Middleware.ts:

Como o I18n não é suportado nativamente dentro do novo router, este é um arquivo essencial para o bom
funcionamento do conjunto. Também é essencial usar o "matcher"
(aqui com valores invertidos que permitem excluir as pastas e arquivos que não devem
ser tratados pelo middleware)

```ts:middleware.ts
import { NextResponse, NextRequest } from 'next/server'
import { locales } from 'app/[locale]/i18n/settings'
import { fallbackLng } from 'app/[locale]/i18n/locales'

export function middleware(request: NextRequest) {
  /* Verificar se um idioma é suportado no nome do caminho: */
  const pathname = request.nextUrl.pathname

  /* Verificar se o idioma padrão está no nome do caminho: */
  if (pathname.startsWith(`/${fallbackLng}/`) || pathname === `/${fallbackLng}`) {
    /* ex: a requisição recebida é: /en/about
    O novo nome de caminho agora é: /about */
    return NextResponse.redirect(
      new URL(
        pathname.replace(`/${fallbackLng}`, pathname === `/${fallbackLng}` ? '/' : ''),
        request.url
      )
    )
  }

  const pathnameIsMissingLocale = locales.every(
    (locale) => !pathname.startsWith(`/${locale}/`) && pathname !== `/${locale}`
  )

  if (pathnameIsMissingLocale) {
    /* Estamos no idioma padrão
    Reescrita para que o next.js entenda */

    // ex: a requisição recebida é: /about 
    // Informar ao Next.js que ele deve se comportar como se fosse: /en/about
    return NextResponse.rewrite(new URL(`/${fallbackLng}${pathname}`, request.url))
  }
}

export const config = {
  /* Não executar o middleware nos seguintes caminhos: */
  // prettier-ignore
  matcher:
  '/((?!api|static|data|css|scripts|.*\\..*|_next).*|sitemap.xml)',
}
```

```
function createTagCount(allBlogs) {
  const tagCount = {
    [fallbackLng]: {},
    [secondLng]: {},
  }

  allBlogs.forEach((file) => {
    if (file.tags && (!isProduction || file.draft !== true)) {
      file.tags.forEach((tag: string) => {
        const formattedTag = GithubSlugger.slug(tag)
        if (file.language === fallbackLng) { // tags para o idioma padrão
          tagCount[fallbackLng][formattedTag] = (tagCount[fallbackLng][formattedTag] || 0) + 1
        } else if (file.language === secondLng) {  // tags para o segundo idioma
          tagCount[secondLng][formattedTag] = (tagCount[secondLng][formattedTag] || 0) + 1
        }
      })
    }
  })

  writeFileSync('./app/[locale]/tag-data.json', JSON.stringify(tagCount))
}
```
